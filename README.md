# 오늘 뭐 먹지? — 모바일 웹앱 (프로토타입 v0.1.0)

**바로 쓰기: https://sungeik.github.io/What-to-eat/** (GitHub Pages로 배포 중)

냉장고에 있는 재료를 고르면, 지금 만들 수 있는 한국 집밥 레시피를 일치율 순으로 찾아 주는 모바일 웹앱입니다.
갤럭시 등 휴대폰 브라우저에서 앱처럼 쓰도록 만들었고, 만족하면 안드로이드 앱(APK)으로 발전시킬 수 있는 1차 프로토타입입니다.

## 파일 구성

이 저장소에는 웹 배포에 필요한 파일만 들어 있습니다. (`index-standalone.html`, `validate.py`, `build_standalone.py`, `serve.sh`, `tests/`는 배포 대상에서 제외)

```
What-to-eat/
├─ index.html          ← 앱 본체 (HTML/CSS/JS 한 파일)
├─ manifest.json       ← 홈 화면에 추가할 때 쓰는 앱 정보
├─ .nojekyll           ← GitHub Pages에서 Jekyll 빌드를 건너뛰게 하는 표시 파일
├─ assets/
│   ├─ banner.jpg      ← 홈 상단 배너
│   ├─ icon-180.png, icon-192.png, icon-512.png
│   └─ (레시피 사진 22장).jpg
└─ README.md
```

## 실행 방법

**방법 1 — 폴더째 열기 (권장)**
```bash
git clone https://github.com/sungeik/What-to-eat.git
cd What-to-eat
python3 -m http.server 8000
# 같은 네트워크의 휴대폰에서 http://<PC의 IP>:8000 접속
```

**방법 2 — 이미 올라가 있는 주소로 열기**
휴대폰 브라우저에서 https://sungeik.github.io/What-to-eat/ 를 연다. (이미지까지 내장된 단일 파일 `index-standalone.html`은 개발 원본 폴더에서만 제공)

**홈 화면에 추가 (앱처럼 쓰기)**
삼성 인터넷·크롬에서 페이지를 연 뒤 메뉴 → `홈 화면에 추가`. 주소창 없이 전체 화면으로 열립니다.

## 화면과 기능

| 탭 | 내용 |
|---|---|
| **홈** | 앱 타이틀·부제, 감성 배너, "냉장고 속 재료를 확인해 볼까요?" CTA, 보유 재료·바로 가능한 요리·저장 수 요약, 오늘의 추천 레시피 4선(재료가 있으면 일치율 순, 없으면 매일 바뀌는 추천) |
| **식재료** | 6개 카테고리 73종 칩 선택, 재료 검색, 없는 재료 직접 추가, 선택 개수 표시, 하단 고정 "이 재료로 레시피 찾기" |
| **레시피** | 검색(이름·재료·분류), 난이도/조리시간 필터, "내 재료로 바로 가능만 보기" 토글, 카드에 보유/필요 재료 수·일치율 막대·부족 재료 표시 |
| **저장** | 하트로 저장한 레시피 목록, 빈 상태 안내와 이동 버튼 |
| **설정** | 식재료 초기화, 저장 레시피 초기화(확인 후), 기본 조리시간(전체/15분/30분), 홈 화면 추가 안내, 데이터 저장 위치 안내 |

**레시피 상세(바텀시트)**: 음식 사진, 분류·시간·난이도·인분, 일치율(%), 재료 목록(가진 재료 초록 체크 / 부족 재료 표시, 소금·식용유 등 기본 양념은 '기본' 표시), 단계별 조리 순서(탭해서 완료 체크, 진행도 표시), 한 줄 팁, (출처가 있는 레시피는) 영상 출처와 새 창으로 열리는 원문 링크, 저장 버튼.
뒤로 가기 버튼을 누르면 상세가 닫히도록 히스토리를 연동했습니다.

## 데이터

- 레시피 **22개** (감자 계란볶음, 감자전, 김치찌개, 계란말이, 참치마요덮밥, 된장찌개, 두부조림, 제육볶음, 간장계란밥, 콩나물국, 떡볶이, 어묵탕, 시금치나물, 부추전, 소시지야채볶음, 김치볶음밥, 미역국, 달걀찜, 카레라이스, 애호박볶음, 두부 두루치기, 아하부장 두부두루치기)
- 식재료 **73종**, 6개 카테고리
- 레시피에 선택 필드 `source`(출처 표기)와 `sourceUrl`(원문 링크)을 넣으면 상세 화면의 팁 아래에 출처 영역이 표시됩니다.
- 모든 데이터는 `index.html` 안의 `INGREDIENTS`, `RECIPES` 배열에 있습니다. 같은 형식으로 항목을 추가하면 앱에 바로 반영됩니다.
- 소금·식용유·후추·설탕·물은 `"pantry": true`로 표시해 "항상 있는 기본 양념"으로 계산합니다(일치율 계산에서 제외).
- `assets/`에 같은 이름(`img` 값 + `.jpg`)의 사진을 넣으면 카드 사진이 바뀝니다. 사진이 없거나 깨져도 `onerror`로 그린 계열 SVG 일러스트가 대신 나옵니다.

## 저장 방식

재료·직접 추가 재료·저장한 레시피·조리 단계 체크 상태는 `localStorage`의 `wte.v1` 키에만 저장됩니다. 서버로 전송하지 않으며, 브라우저 데이터를 지우면 함께 사라집니다.

## 배포

- GitHub Pages (branch `main`, `/` 루트) — https://sungeik.github.io/What-to-eat/
- `manifest.json`의 `start_url`은 `./index.html`, 아이콘 경로는 `assets/...` 상대경로라 서브패스 배포에서도 따라옵니다.

## 검증

정적·동작 검증 스크립트(`validate.py`, `tests/`)는 개발 원본 폴더(`projects/what-to-eat/`)에 있으며, 이 저장소를 만든 시점의 결과는 다음과 같습니다.

```bash
python3 validate.py      # 데이터 정합성, HTML 태그 균형, CSS 변수/괄호, JS 괄호, id/data-act 참조, 브리프 항목
pip install quickjs && python3 tests/run.py   # 실제 동작 검증 (두 버전 모두)
```
- 정적 검증: 통과 (오류 0)
- 동작 검증: QuickJS로 앱 스크립트를 실제 실행해 81개 항목 확인 (탭 이동, 재료 선택/해제, 일치율 계산, 필터·검색, 상세 시트, 출처 표시, 단계 체크, 저장/해제, 초기화 확인창, localStorage 복원, 이미지 폴백, HTML 이스케이프) — `index.html`과 `index-standalone.html` 모두 81/81 통과
- 사진 22장은 모두 실제 요리 사진 스타일로 생성해 `assets/`에 저장했습니다.
